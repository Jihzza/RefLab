Note here the following:

* Think of /auth/callback as a landing route whose only job is to finish an OAuth login that started somewhere else (Google’s consent screen). It’s not a Supabase “feature page” — it’s your app’s route that completes the flow. 
* From your login UI you call: supabase.auth.signInWithOAuth({ provider: 'google', options: { redirectTo: 'https://reflab.com/auth/callback' } })
    Supabase redirects the browser to Google, and Google will redirect back to your redirectTo URL afterwards.

Authentication map (archived; intentionally non-executable)

Do not copy configuration or authentication snippets from this historical file.
The production implementation is the only canonical source:

* apps/frontend/src/lib/supabaseConfig.ts validates and resolves the allowed
  public browser configuration and prevents production services from being used
  by preview builds.
* apps/frontend/src/lib/supabaseClient.ts owns the explicit storage key and the
  browser lock used by Supabase Auth. No feature may read raw VITE_* variables or
  create a second client.
* apps/frontend/src/features/auth/api/authApi.ts owns password, OAuth, recovery,
  metadata, deletion and logout requests. Sensitive mutations bind a captured
  bearer token to its expected user and use compare-and-swap storage semantics.
* apps/frontend/src/features/auth/api/authErrors.ts owns the exhaustive error
  classifiers used by the UI and their tests.

Any future authentication change must update those modules and their focused
tests; this document must never be treated as a runnable setup guide.
1. Current session ownership invariants (non-executable reference)

See apps/frontend/src/features/auth/components/AuthProvider.tsx. Its current
implementation is intentionally more defensive than the former draft above:

* the auth listener and bootstrap are revision-ordered, so an older async result
  cannot overwrite a newer account;
* every account-scoped operation captures both access token and expected user;
* destructive mutations verify identity before and after the request and never
  remove a replacement account's persisted session;
* password-recovery and legal-acceptance state are keyed and remounted by owner;
* the message outbox is paused and quiesced during account transitions;
* identity mismatch fails closed and signs out only the captured replacement
  session that was proven unsafe.

The boundary behavior is enforced by AuthProvider.test.tsx, authApi.test.ts and
AuthPublicOwnerBoundaries.test.tsx. Preserve those invariants when changing Auth.

1. RequireAuth, routing protection guard

// apps/frontend/src/app/RequireAuth.tsx
import React from 'react'
import { Navigate } from 'react-router-dom'
import { useAuth } from '@/features/auth/components/AuthProvider'

export default function RequireAuth({ children }: { children: React.ReactNode }) {
  const { status, session } = useAuth()
  if (status === 'busy' || status === 'idle') return <div>Loading…</div>
  if (!session) return <Navigate to="/login" replace />
  return <>{children}</>
}

1. OAuth callback page (PKCE exchange)

// apps/frontend/src/features/auth/components/OAuthCallbackPage.tsx
import React, { useEffect } from 'react'
import { useNavigate, useSearchParams } from 'react-router-dom'
import { exchangeCodeForSession } from '@/features/auth/api/authApi'
import { useAuth } from '@/features/auth/components/AuthProvider'
import { mapAuthError } from '@/features/auth/api/authErrors'

export default function OAuthCallbackPage() {
  const [params] = useSearchParams()
  const nav = useNavigate()
  const { setBusy, setError } = useAuth()

  useEffect(() => {
    const run = async () => {
      const code = params.get('code')
      if (!code) {
        setError('Missing OAuth code.')
        return
      }

      setBusy(true)
      const { error } = await exchangeCodeForSession(code)
      setBusy(false)

      if (error) {
        setError(mapAuthError(error, 'oauth').message)
        return
      }

      nav('/dashboard', { replace: true })
    }

    run()
  }, [])

  return <div>Signing you in…</div>
}
