# Security policy

## Supported version

Until RefLab publishes versioned releases, only the current production commit
on `main` is supported with security updates.

## Report a vulnerability privately

Do not open a public issue or discussion for a suspected vulnerability. Use
[GitHub private vulnerability reporting](https://github.com/Jihzza/RefLab/security/advisories/new)
so the repository maintainers can assess the report without exposing users or
deployment details.

Include the affected route or component, impact, minimal reproduction steps and
any suggested mitigation. Use synthetic data, redact credentials and tokens,
and do not access, modify or retain another person's data while testing.

For privacy requests or non-security product support, use the RefLab support
form instead. The operational owner and response targets for both channels must
be assigned in the launch runbook before production launch.
